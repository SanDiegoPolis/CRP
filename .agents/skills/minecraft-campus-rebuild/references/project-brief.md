# 每个高校项目单独记录的参数

新建或接续时按实际需要读取。可以使用现有项目配置或一页 `planning/project-brief.md`，不要求为本技能迁移原工程格式。

## 最少要知道什么

| 参数 | 记录内容与决策 |
| --- | --- |
| 学校身份 | 正式名称、城市/国家、项目短名；区分名称相近的高校 |
| 校区与边界 | 具体校区、包含的生活区/附属区；多个不相连校区分别确定坐标与交付范围 |
| 目标年代 | 指定历史时期或当前公开资料可核实的状态；来源日期与建筑实际状态分别记 |
| 游戏目标 | Java/Bedrock、准确版本、原版方块或允许的模组/资源包；不自动升级版本 |
| 输出 | 可打开的世界、整校单文件原理图、分区/分栋组件，或只修正已有成品 |
| 比例 | 统一写 `blocks_per_meter`，即一米对应多少方块；允许范围、竖向比例、可微调项另记 |
| 建造范围 | 地标、全校建筑、道路园林、外观、入口大厅或完整室内；未知室内可否设计补全 |
| 基准 | 原图/原存档/组件清单的位置与摘要、正式版本、坐标版本 |
| 本地路径 | 项目目录、成品目录；安装或同步时使用用户确认的实际实例目录 |
| 完成条件 | 本轮要交付的文件、需通行的路线、要求的游戏实测及允许保留的资料缺口 |

用户已经给过的值直接沿用。校区、游戏版别/版本等会改变成果的关键缺项才询问；尚未确定导出格式时仍可先开展资料核实。学校名称不明确时不要猜成另一所大学。

没有比例偏好时，先根据校园范围、可辨认细节和设备容量估算，并说明采用的比例。用户给定 1:1 到 2.5:1 等范围时只在该范围内选择。用户提供带固定格数的 schematic 或地图时，以该基准优先，不能另套默认米制比例。

## 可直接采用的项目摘要

按实际信息填写；未知项写“待确认”及其影响，不填假值。

```text
学校 / 校区 / 目标年代：
本轮范围与交付格式：
Minecraft 版别 / 版本 / 方块依赖：
blocks_per_meter / 允许的局部调整：
室内范围 / 设计补全约定：
项目目录 / 输出目录：
正式资产清单与摘要：
坐标版本 / 原点 / XZ 轴向 / Y 偏移：
已授权的游戏实例与 saves 目录（无则留空）：
本轮完成条件 / 未核实事项：
```

游戏实例、用户姓名、绝对路径、Java 可执行文件和服务端缓存位置只放在项目配置中，不回写为通用技能默认值。记录“验证后同步”的既有授权；它不表示创建了后台监控或定时任务。

## 从现有工程接续

1. 查用户指定目录、项目级说明与实际文件；路径失效时查工作区索引或再询问位置，不创建同名空工程冒充找到。
2. 分别识别候选修改、正式模型、导出世界、压缩包、游戏安装副本。优先比对清单摘要、来源与验证报告，修改时间只能作线索。
3. 核对当前坐标变换与目标版本。旧阶段的数据计数、楼名、待办和完成状态不能直接沿用到另一版本。
4. 把本轮改动及完成证据挂到对应发布版本。进度查询不要求先重新生成全部摘要；重建、发布或替换存档前才做相应核对。
