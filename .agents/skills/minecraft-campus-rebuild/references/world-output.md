# 输出可打开的游戏存档

仅在用户需要世界存档或版本迁移时读取。随包 `.schem` 工具不负责世界输出；沿用项目已有导出器，或为目标版别/版本选用并验证合适的写出实现。

## 版本与输出方式

- 从项目参数确定 Java 或 Bedrock、完整版本及是否要求原版。版本号、DataVersion、方块状态表、NBT 字段、世界高度和目录结构分别核实，不能只改 `level.dat` 的版本标签。
- 优先用相同版本游戏生成的干净小世界作为元数据参照。读取已有玩家世界前分清其修改与本项目生成内容，不能把玩家背包、身份、进度作为新校园默认数据。
- 导出器应接受项目根目录、世界名、变换、目标版本和输出路径。避免跨学校绝对路径、导入模块即重写输出、共享变量决定输出位置。
- 先导出含地面、斜向建筑、入口、楼梯、中文标牌等实际需要数据的小样，独立回读并在目标游戏运行时检查，再扩大到全校。方块实体、实体、光照、地形和生物群系需要与所选格式一起保留或明确构造。
- Bedrock 使用其实际世界格式和验证方式，不能改扩展名冒充转换；不能用 Java 服务端验证结果替代 Bedrock 测试。

## Java 世界目录具有版本差异

传统主世界区块通常在 `region/*.mca`；Java 26.1 的存储变更将主世界移至 `dimensions/minecraft/overworld/region/*.mca`，其他默认维度和玩家数据也有迁移。具体导出以目标版本为准。[官方 26.1 World Storage 说明](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-1)

`scripts/audit_release.py --world ...` 能识别传统与命名空间维度目录，但它只检查文件身份/目录存在性，不解析 NBT、不确认版本匹配，也不转换世界。两个主世界路径同时有文件时应查清哪份生效，不能把重复资产算成更多已建区块。

## 世界验证

1. 验证使用到的方块及属性，拒绝未知状态或未经允许的模组方块。
2. 从最终区域文件独立读取已创作的区块/区段；比较坐标、调色板还原的方块、方块实体及出生点，确认没有遗漏、重复或空气删除丢失。大型世界可以分区遍历，不能只抽查一个区域就声称全量通过。
3. 记录世界坐标下的通路探针，至少覆盖本轮要求的入口、楼梯、桥头和高差。模板通过后仍需检查旋转/拼接后的实际世界。
4. 使用对应版本客户端或官方服务端真正加载目标世界；大地图按运行时限制分批加载，检查日志、地标、光照保存和正常关闭。无玩家时的暂停、强加载上限等按所用版本配置，不能让未完成任务的静默服务端被误记为通过。
5. 客户端画面、夜景和性能单独报告。没有客户端环境时明确“服务端加载通过，客户端未测”，仍可交付已验证的文件；运行时也不可用时不能声称“已确认可在游戏中打开”。

## 最终保存与安装

- 配置安全出生点、朝向和用户所需模式；从最后保存的文件再次核对。演示用校园可采用创造模式、稳定日照，用户要求生存等模式时按用户设置。
- 运行验证可能改写文件。待运行时正常关闭后才打包、计算最终摘要和复制；不要同步正在打开的世界或沿用运行前的文件哈希。
- 用户指定同步目录时只复制游戏世界文件夹。项目源码、参考资料、ZIP 和外层预览留在项目中；运行时锁文件由游戏自行创建。先确认对应世界已关闭，更新同名世界前保留可恢复备份，遵循用户对游戏内改动的保留要求。
- 在目标实例下核对 `世界文件夹/level.dat` 与该版本区块目录；按实际复制文件集合比对摘要并保存安装记录。已有授权内的正常交付直接执行，环境权限审批按工具要求处理。

交付说明包含世界名、目标版本、比例、出生点/传送位置、安装路径、已测试范围与资料精度。不把当前使用的游戏目录或某个学校的传送点写入技能默认设置。
