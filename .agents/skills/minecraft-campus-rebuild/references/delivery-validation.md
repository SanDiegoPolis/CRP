# 差分、验收与交付

## 正式资产与差分约定

沿用已有格式，不必为使用技能改造工程。新工程可使用如下结构：

```text
reference/                原始资料、来源和截帧
planning/                 范围、坐标版本、对象清单、问题和阶段记录
tools/                    本项目生成及校验程序
output/campus_<version>/  本版组件、manifest、核查记录和预览
output/<version>_World/   level.dat、目标版本的区块/维度目录、游览说明
```

推荐 manifest 的最小实用信息为 release、coordinate_version、目标游戏版本及 files。每个 files 条目记录 file、sha256、offset_xyz、size_xyz、non_air_blocks；palette 和来源字段按需要加入。此处是工作约定，不是 Sponge 或 Minecraft 官方文件规范。

差分至少记录基准 manifest 哈希、坐标版本、全局模型 xyz、before、after、palette 和来源分组。空气也是有效 after 状态。不同补丁的 palette 序号需先映射到同一方块状态表，不能直接拼数组。

合并前验证基准未变、补丁坐标唯一、before 与正式组件组成的基准逐格相符。同坐标同 after 可去重；不同 after 是冲突，应根据来源或任务意图解决，不能依赖文件遍历顺序。

维护方块归属：清除属于旧资产的构件后，再写入替换资产；否则旧墙、屋顶、树木会在叠加时复现。`忽略空气粘贴` 不能完成删除。入口修正可跨建筑文件与场地组件，但交付时说明组合关系，避免把残缺单件当完整楼体。

规模较大时使用稀疏补丁、区域/瓦片处理、分层数组或内存映射。稠密全校数组不是一概禁止，但应先算尺寸与内存，不默认申请整校园最大高度体积。

## 分层验收与停止条件

| 层级 | 检查内容 | 能支持的结论 |
|---|---|---|
| 文件身份 | 清单、路径、哈希、目标版本、ZIP | 文件完整、对应本版 |
| 组件几何 | 各组件重新读取后独立合成，核对最终体素、删除、重叠、保护区域 | 合并正确 |
| 空间功能 | 入口、步道、道路、桥头、净空、高差、构件接地 | 指定检查模型下通路通过 |
| 视觉核对 | 实际体素多视角、与证据对照、整体上下文 | 所检查部位的形态符合程度 |
| 世界格式 | 每个已写创作区段独立读取比较、区块/区段遗漏和重复、出生点及元数据 | 世界数据写入正确 |
| 游戏加载 | 对应版本客户端或服务端加载并保存目标存档，检查日志、地标及光照 | 所测世界能被对应运行时加载 |
| 客户端体验 | 实际客户端巡视指定路线、夜景及帧率/卡顿 | 所做客户端场景的运行表现 |

各项检查通过且没有新修改或未解决问题时，不无限重复全量测试。追加修改后重跑受影响检查，并在最终合并版本执行必要的整体检查。

报告必须绑定文件哈希或版本。旧检查的 PASS 不能套到后来修改的补丁。辅助检查器只读取已有检查报告时，输出应称“已有报告声称”，不能冒称它独立完成了几何或游戏验证。

## 通路检查的精度

构建地面支撑高度、可通行材料和净空，而非仅看二维颜色。半砖分上/下/双层；楼梯可用保守碰撞包络初检，对误判风险高的入口补细分几何或游戏验证。树叶、栏杆、墙、门状态不能都当作普通实心或空气。

步道种子应在既有路面，目标涵盖本轮实际应接通区域。车行连接额外检查最窄宽度及净空，可对车道路面做侵蚀后再查连通；侵蚀半径应有车辆或项目宽度依据。

每侧入口分别限定其接近区域，检查“道路→本侧门槛→本侧门洞→门内紧邻平台”。外观项目的入口平台验证不代表完成室内走廊、房间或消防通行。

合并后重新查与其他补丁的相互影响。候选单独通过，不等于最终世界同样通过。构件接地检查区分原有问题和本次新增悬空；不能为消除告警无依据地往桥下填实。

## 世界与原理图导出

先辨别 `.schematic`、`.schem`、`.litematic`、Java Anvil 世界与 Bedrock 世界；改扩展名不会转换格式。软件版本、方块状态、DataVersion、NBT、压缩和 palette 编码应按目标版本的当前规范核实，不把旧项目参数当通用常量。世界输出详见 [world-output.md](world-output.md)。

从现有世界模板借元数据时，读取正确版本，排除不需要的玩家身份、物品和进度。用安全出生点与明确的模型到游戏 Y 偏移；首次游戏重算光照只表示一种写出策略，不是夜景已验收。

用户要整校单个原理图时，完整合成所有被清单引用的组件与空气删除结果，并给出粘贴原点和对齐说明。若所选格式或客户端容量不能合理承载，具体说明体积和限制，再交付可用替代，不用地面文件冒充全校。

## 发布记录

同一版本关联世界、模型包、预览、校验和说明；发布说明写最终结果，不保留互相矛盾的“最新”状态。历史记录可留，但必须可辨别。

安装独立世界时确认目标实例的 saves 路径，用新目录避免覆盖玩家改动；复制后逐文件核对。用户要求原址替换时先明确保留策略。已有任务授权内的正常交付不额外增加确认环节；实际权限限制按环境处理。

ZIP 检查除压缩完整性还应核对预期根目录和内容集合，必要时逐项与源文件比对。Java 整校世界包要包含 level.dat 与目标版本的区块目录；Bedrock 包按其世界格式核对；模型包要包含所有清单组件。

最终答复给出版本、主要改动、检查结论、可点击成果、使用入口和真实限制。游戏窗口不可操作时保留交付并写未测试，不将渲染图或文件校验替代实测。
