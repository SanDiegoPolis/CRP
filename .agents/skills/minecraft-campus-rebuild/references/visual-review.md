# 固定视角对照与完成条件

用于回答“是否像实景”“这一轮是否可交付”。文件回读通过之后，仍须单独进行本流程。

## 建立可复查的对照

每个关键对象建立一行记录，保存为项目内 JSON/CSV：

| 字段 | 内容 |
|---|---|
| object_id / view_id | 稳定的对象与视角编号 |
| source | 原照片或航拍位置、来源、拍摄年代、文件摘要 |
| target_release_sha256 | 本次实际渲染的发布清单摘要 |
| camera | 位置、目标点、投影方式、视野或正交尺度、裁剪区域 |
| render | 从实际模型生成的图片路径及摘要 |
| observations | 平面、体量、层数、屋顶、立面节奏、入口、地面关系逐项结论 |
| confidence / gaps | 已证实、推定、缺资料；说明遮挡、时代差异、透视影响 |
| decision | pass / partial / fail，检查人、时间、下一步及完成证据 |

取总览、主要立面和入口地面视角；选择应覆盖当前风险，不机械规定所有项目同一数量。斜视图先对齐可确认的地面控制点，不通过拉伸模型迎合照片透视。重做后复用同一相机与裁剪，确保差异来自模型。

把原图与实际模型图并排展示，并指出具体问题位置。无需统一给出相似度分数；轮廓、屋顶或入口偏差比一个没有测量方法的百分数更有用。遮挡部分保留未核实，不把“没有发现问题”当作证据齐全。

## 缺口决定下一步

优先修正会连带影响其他工作的坐标/时代错误，其次是落位、体量、主路与入口，再处理立面细节和装饰。缺照片时先列出需要确认的具体问题、目标视角及已有证据，不无目的扩大搜索。

每个动作要有可观察的完成条件。例如“本侧入口从相邻道路到门洞可连续步行，录制或保存实际通行检查，并补上同视角实景对照”；不能只写“优化东门”。

## 对本轮完成下结论

- 组件覆盖：本轮范围内的对象均有成品或明确缺口。
- 文件一致：最终文件可回读，与已审模型一致。
- 几何与路线：关键净空、高差、接地、入口连通在最终版本检查。
- 视觉依据：关键外观有对应资料及对照，推定项明确标识。
- 游戏实测：加载、粘贴/出生位置、游览和性能按实际测试记录。

哪些条件是交付必需由用户范围决定。若只完成文件导出，可报告“导出完成、视觉与游戏未测试”；不能把其余条件一并勾为通过。通用工具不替代上述视觉判断或游戏实测。
