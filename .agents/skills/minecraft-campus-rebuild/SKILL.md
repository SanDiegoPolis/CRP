# Minecraft 高校校园复原

将真实高校资料转成布局可信、地标可辨认、指定路线可游览的 Minecraft 成果。支持不同学校、国家、校区、时代与游戏版本。学校和版本数据属于项目；本技能不携带任何学校的既有模型、固定比例或个人电脑路径。

## 先判定本次范围

- **新建校园**：先识别学校与校区，记录游戏版别/版本、比例、输出、室内范围和资料基准。读 [项目参数](references/project-brief.md)，只补会影响结果的缺项。
- **接续或局部返修**：先定位正式资产、上次发布、验证报告和安装副本；复现本轮问题后修改对应范围。不要自动重做全校或换坐标系。
- **仅导出或安装**：直接检查已有成品与目标格式，不重复研究和建模。按 [交付验收](references/delivery-validation.md) 执行。
- **询问进度或文件位置**：核实文件与已有报告后回答；无需启动生成、渲染或全量测试。

沿用用户在当前会话中已确定的游戏版本、比例范围、工作目录和同步位置。学校有多个校区且无法判断时，询问一次校区；可以同时查公开资料。其余可推断的设置给出合理假设并继续，不反复征求同一授权。新增学校建立独立工程，不继承上一所学校的坐标、计数或传送点。

## 从资料到成品

制作或几何返修时读 [资料与建模](references/reconstruction.md)，按当前缺口推进。

1. **建立证据与清单。** 优先学校官方地图、可定位的实景照片、航拍及用户资料。区分竣工实景、施工中和规划效果图；记录来源年代、视角、对象与不确定项。列出建筑、校门、连廊、道路、桥、水岸、运动场和生活区；地图轮廓数不等于真实楼栋数。
2. **固定坐标与比例。** 保存原始底图、原点、轴向、方块/米、模型 Y 到游戏 Y 的映射及坐标版本。用分散的控制点核对。示意图仅支持估算；用户给出的原格数、边界或锚点优先。允许微调时记录对象与偏移，不能为方便摆放整体打乱布局。
3. **先做代表建筑。** 用地标、斜向建筑或庭院组团验证落位、入口、屋顶与离散采样。图书馆、塔楼、体育馆等各自建模；只有外形确实重复的宿舍等才复用模板，并逐栋核对尺寸、朝向和入口。避免用同一种方盒子替代所有建筑。
4. **补齐场地与可游览空间。** 核对建筑各侧的前庭、后勤硬地、停车、步道、绿岛、地形、水岸和桥头。室外路线不得穿过封闭楼体；庭院、架空层与连廊下的真实通道应保留。室内按用户范围实施，设计补全与真实复原分开说明。
5. **合成并复核实际成果。** 在同一坐标版本合成；返修记录 before/after 与构件归属，空气删除也要写入成品。对输出文件独立回读，检查碰撞、入口、净空、楼梯和接坡。新修改只重跑受影响检查，并完成最终版本必要的整体核对。
6. **导出、交付与同步。** 世界存档读 [世界输出](references/world-output.md)；原理图读 [工具说明](references/toolkit.md)。用户要能直接进入游戏时，继续完成世界输出与验证，不能以生成脚本、规划或分件模型代替所需存档。已授权的游戏目录同步在最终验证后完成，记录安装副本的身份。

## 判断是否完成

读 [视觉核对](references/visual-review.md)，对本轮重点部位进行同视角或可比视角检查。预览从最终文件所对应的实际方块生成；AI 概念图、旧数组或仅换校名的旧预览不能作为验收依据。

分别记录文件、几何、路线、视觉、世界格式和游戏运行的结果。服务端成功加载可以证明所测世界可加载，不能证明客户端画面、帧率或外观准确；只做离线回读时如实写未运行游戏。楼栋覆盖率、记录数量与“相似度”不是同一指标。

资料不足时保留可核实部分并标出补全；缺口是否阻塞由本轮目标决定。达到目标且必要检查通过后交付，不因无关历史问题无限扩大工作。

最终提供：学校/校区、目标游戏版本、比例与范围、可点击成品、打开或粘贴方法、主要验证结果与实际限制。按需附导览、传送坐标和实际模型预览。已同步时给出目标世界文件夹及校验结果；未同步时说明真实原因。

## 随包工具及边界

以下工具从**本技能目录**解析，项目路径通过参数传入。完整参数、依赖和格式见 [toolkit.md](references/toolkit.md)。

| 工具 | 用途 | 边界 |
| --- | --- | --- |
| `scripts/campus_build.py` | 查看组件规模、合并稀疏补丁、导出整校 `.schem` | 仅 Sponge v2 方块数据；不转换游戏版本，不输出 Anvil/Bedrock 世界，不丢弃不支持的数据 |
| `scripts/audit_release.py` | 清单摘要、声明报告、Java 世界目录和 ZIP 完整性检查 | 不读取体素或运行游戏；不证明 ZIP 与发布目录逐文件相同 |
| `scripts/project_state.py` | 区分候选、发布、世界和安装副本；发现过期报告 | 记录检查不等于执行检查；旧项目不必先补齐账本才能接续 |
| `scripts/test_toolkit.py` | 用临时小型样例验证工具数据处理 | 不接触正式校园，也不代表新校园已经验收 |

这些脚本是便携工具集，不是自动生成任意高校的完整引擎。新项目需要根据资料编写或适配建筑生成器、目标版本世界导出器和渲染器；已有项目优先复用经核验的能力。
